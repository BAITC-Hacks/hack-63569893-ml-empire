# Frontend: сценарии, датасет, оценка и аудиодиагностика

Дата: 23.09.2026. Все перечисленные клиентские функции входят в текущий объём по запросу владельца frontend, включая пункты, названные дополнительными в исходном ТЗ. Реализация интерфейса не является гарантией 100 баллов или доказательством качества серверных моделей. Выполненные проверки: [frontend-verification.md](frontend-verification.md).

Навигация: «Разговор», «Сценарии», «Диалоги датасета», «Оценка и сравнение», «Микрофон и звук». Во время записи/обработки/воспроизведения переход блокируется, чтобы активный аудиопроцесс не оказался скрытым. RU/KK меняет интерфейс, но не переводит исходные данные или ответ сервера.

## 1. Редактор сценариев

Источник: `datas/scenarios.json`; допустимые слоты/действия/очереди: `datas/slots.json` и `datas/actions.json`.

1. Найдите сценарий по ID, названию или описанию.
2. Измените название, описание, приоритет, признаки fast-path/идентификации/подтверждения. Полный JSON позволяет изменить примеры RU/KK, ответы, слоты, действия, исключения и системные намерения.
3. Исправьте показанные ошибки и нажмите «Применить к черновику». Неприменённые изменения не экспортируются. «Отменить правки» возвращает сохранённую запись.
4. «Новый сценарий» добавляет дополнительную запись; удалить можно только дополнительную запись без нарушенных ссылок. SC01–SC40 и три исходных системных намерения нельзя удалить.
5. «Экспорт JSON» сохраняет `scenarios.local-draft.json`. Передайте файл backend-разработчику для проверки и применения. Файл не меняет маршрутизатор автоматически.

Валидация проверяет структуру/типы, уникальные ID и slug, ссылки на сценарии/слоты/действия/очереди, RU/KK-поля и обязательное `requires_confirmation` при необратимом действии. ID существующей записи неизменяем. Импорт ограничен 2 МиБ; импорт, сброс к исходнику и удаление требуют подтверждения.

Применённый черновик сохраняется в `localStorage` под `voice-router.catalog-draft.v1`. При запрете хранения показывается предупреждение: экспортируйте результат до закрытия. Повреждённый сохранённый JSON не считается валидным каталогом. Используйте только синтетические примеры; редактор не превращает произвольный импорт в обезличенные данные.

**Граница интеграции:** существующий `GET /catalog/scenarios` возвращает краткий каталог только для показа в супервизоре. Он не является CRUD-API редактора. Публикация, серверные версии, аудит и авторизация должны быть согласованы отдельно. В интерфейсе нет фиктивной кнопки «Опубликовано» и не заявляется применение локального JSON к звонкам.

## 2. Проигрыватель размеченных диалогов

Источник: все 10 диалогов `datas/dialogs_sample.json`.

### Локальный эталон

Выберите диалог и режим «Эталон». Доступны показ по таймеру, пауза, следующая реплика, начало и показ целиком. У каждой реплики есть автор, язык и раскрываемая разметка. Персональные синтетические значения маскируются при отображении.

Это чтение заранее записанного **текста**, не вызов модели, не TTS и не запись реального разговора. В этом режиме запросы по диалоговым репликам не отправляются.

### Пошаговый прогон через API

1. Выберите «Прогон через API» и нажмите «Новая сессия для прогона». Это очищает текущую историю разговора. Настоящий подключённый сервер может использовать платных AI-провайдеров.
2. Дождитесь готовности сессии. Нажмите «Отправить эту реплику». В обычный `turn.text` уходит только синтетический текст клиента: **без** эталонного ответа, ожидаемых сценариев, слотов или тегов.
3. Дождитесь терминального состояния соответствующего `turn_id`. Фактические сценарии и ответ показаны отдельно от ожидаемого. «Открыть трассировку» связывает шаг с обычным супервизором.
4. Перед потенциальным подтверждением действия проверьте фактический preview и явно отметьте согласие на отправку показанной реплики. Ни таймер, ни эталонное «да» сами ничего не подтверждают.
5. Скачайте `<dialog_id>-results.json`: результаты содержат сопоставление сценариев и маскированную трассу.

Отправка после прерывания или изменения сессии не продолжается автоматически. Серверный `turn.complete` относится к обработке, а не к доказанному исполнению бизнес-действия. Отмена ожидания не является серверной командой отмены/удаления.

Сравниваются только primary и множества сценариев, а также recall ожидаемых меток. Это **не** автоматическая оценка фактов ответа, слотов, действий, языка ответа или hidden-набора. Диалоговый экспорт отличается от формата `dev_utterances` ниже; не загружайте его как dev-предсказания.

## 3. Оценка маршрутизатора и Full/Fast

Экран «Оценка и сравнение» работает локально. Он не вызывает LLM и не включает fast-path на сервере. Backend-разработчик передаёт JSON-предсказания фактического прогона по `datas/dev_utterances.json` (104 записи, версия `1.0`).

### Формат импорта

Базовый формат совпадает с `datas/evaluate.py`; массив задаёт порядок выбранных сценариев. Строковое значение также поддерживается как один сценарий.

```json
{"U001":["SC01"],"U002":[]}
```

Пустой список означает предоставленный ответ без маршрута. Отсутствующий ключ означает отсутствующий результат. Оба случая дают ошибку относительно непустого эталона, но различаются в покрытии/диагностике.

Для таймингов поддерживается обёртка:

```json
{
  "dataset_version": "1.0",
  "label": "run-name",
  "predictions": {"U001": ["SC01"], "U002": []},
  "latency_ms": {"U001": 350},
  "latency_stage": "router"
}
```

Это **пример формата**, не фактическое измерение или правильный ответ на U001. `label` и произвольные метаданные не используются и не экспортируются. `latency_stage`: `router` либо `end_to_end`; без него отдельная медиана показывается как измерение неизвестного этапа, но сравнение времени не выполняется.

- Файл или вставленный JSON: до 1 МиБ. Некорректный JSON, неизвестные/дублирующиеся сценарии, неверные типы и несовпадающая версия отклоняются.
- Неизвестные ID реплик исключаются с видимым счётчиком; сырые неизвестные ID не попадают в отчёт.
- В `latency_ms` допустимы конечные числа 0–600 000 мс для предоставленных результатов. Непредоставленный тайминг не равен нулю.
- Не включайте тексты клиентов, API-ключи или внутреннюю диагностику. Импорт не отправляется серверу.

### Формулы и знаменатели

| Показатель | Правило |
| --- | --- |
| Primary accuracy | Первый предсказанный сценарий совпал с первым эталонным / все 104 реплики |
| Full match | Множества сценариев полностью совпали / все 104 реплики |
| Intent recall | Число найденных ожидаемых интентов / число всех ожидаемых интентов только у `multi_intent` |
| Язык / тип | Те же primary/full, знаменатель: все эталонные записи группы, включая пропуски |
| Покрытие | Число известных ID с предоставленным результатом, включая пустой список |
| Full match по загруженным | Отдельный справочный показатель, не замена полной оценке |
| Доля SYS_UNCLEAR / SYS_OUT_OF_SCOPE | Число предоставленных ответов с соответствующим **первым** сценарием / число предоставленных ID |
| Ошибки сценария | Пропущен: ожидался, но не найден. Лишний: предсказан, но не ожидался. Несовпадения: ошибки полного набора среди реплик, ожидающих сценарий |
| Confusion | Неправильные пары первого ожидаемого/предсказанного сценария; отсутствие маршрута и отсутствие результата различаются |
| Медиана задержки | Только переданные валидные измерения; рядом показаны их число и этап |

Отсутствующие ID считаются ошибками, как в `datas/evaluate.py`. Multi-intent входит в несколько строк сценарной таблицы, поэтому их суммы не являются числом уникальных ошибочных реплик.

### Сравнение

Загрузите два независимых результата в Full path и Fast path. Эти имена назначает пользователь; фронтенд не доказывает, какой алгоритм реально выполнял сервер.

Качество сравнивается только по общим ID; отдельно показаны непарные результаты. «Fast − Full» выражает разницу точности в процентных пунктах. Изменение полного совпадения по каждой паре даёт число улучшенных/ухудшенных реплик.

Время сравнивается только на общих ID с измерениями **обоих** прогонов и одинаковым явно указанным этапом. Помимо двух медиан показывается медиана парных разниц; это разные статистики. Отрицательная разница времени означает более быстрый Fast. Неполное покрытие не скрывается.

«Скачать отчёт» сохраняет `voice-router-evaluation.json`: сводки, ошибки по ID/меткам и парное сравнение без исходных реплик, импортированных названий и произвольных метаданных. Это оценка предоставленных результатов на dev-наборе, не гарантия качества hidden-набора или банковских баллов. Fixture не подходит для такой оценки.

## 4. Эмоция и тон ответа

Супервизор показывает данные `trace.affect`, только если сервер передал распознаваемую эмоцию или тон. Источник: `audio`, `text`, `multimodal`; оценка 0–1 обозначена как оценка модели, не объективный диагноз/вероятность.

Эмоции: `neutral`, `concerned`, `frustrated`, `angry`, `sad`, `positive`. Тон ответа: `neutral`, `empathetic`, `calm`, `reassuring`, `concise`. Отсутствующие или неподдерживаемые значения не заменяются догадкой по словам.

Это готовый клиент для **аддитивного предложения контракта**, а не обещание наличия анализа эмоций в текущем backend. Сервер определяет эмоцию и реально адаптирует текст/голос. Перед merge согласуйте отображение серверной модели в [trace.affect](frontend.md#эмоции-и-тон-аддитивное-предложение-контракта). UI не меняет TTS локально.

## 5. Микрофон и звук без AI-сервера

Экран «Микрофон и звук» предназначен для аппаратной проверки на localhost/HTTPS. Нажатие «Записать тест» запрашивает разрешение. Запись ограничена 15 секундами и хранится только в памяти вкладки; при выходе ресурсы освобождаются, запись удаляется. Зависший запрос разрешения также ограничен; позднее разрешение после отмены не запускает запись заново.

Используются те же `PcmRecorder`, `PcmPlayer` и детектор тишины, что в разговоре: PCM16 LE, mono, 24 kHz. Доступны устройство/обновление списка, уровень и пик RMS, ручной stop и автозавершение. Порог речи 0.005–0.08; пауза 800–2500 мс. Начальная тишина не запускает завершение, слишком низкий порог может принять шум за речь.

Для воспроизведения есть локальное прослушивание записи, двухсекундный синтетический тон, stop и mute. Показатель до первого звука отсчитывается браузерными часами при тесте проигрывателя: **это не** LLM/STT/TTS latency и не измерение физического динамика. Ни звук, ни запись здесь не отправляются API/AI-провайдерам.

Проверка требует участия человека: произнести синтетическую фразу обычным и тихим голосом, подтвердить слышимость, проверить разрешение/запрет, сменить/отключить доступное устройство и убедиться, что индикатор микрофона погас. Нельзя отметить hardware-пункт выполненным только по unit-тесту или наличию индикатора.

## Передача backend-разработчику

- Базовый [HTTP/WebSocket-контракт](frontend.md), включая корректные `turn_id`, route/trace и snapshot.
- Для эмоций: явное согласование `trace.affect`; не подставлять демонстрационную оценку в production.
- Для каталога: экспорт локального JSON и отдельно согласованный механизм применения/версий/доступа. В текущем контракте записи каталога нет.
- Для оценки: predictions по всем 104 ID; опционально сопоставимые реальные тайминги. Политики Full/Fast и запуск моделей контролирует сервер.
- Для диалогового прогона: обычный текстовый API с состоянием сессии; метки и эталонные ответы остаются на клиенте.

Точные результаты Chrome, физического устройства, регрессии и интеграционные ограничения поддерживаются в [чек-листе](frontend-verification.md), не выводятся из факта наличия новых экранов.
