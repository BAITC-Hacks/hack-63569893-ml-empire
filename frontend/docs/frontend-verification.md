# Проверка фронтенда Voice Router

## Статус на 23.09.2026

Реализован клиент и отдельный синтетический HTTP/WebSocket fixture. Код backend находится в рабочей копии, но перечисленные ниже клиентские проверки не подтверждают приёмку реальных LLM/STT/TTS. [Матрица покрытия](requirements-coverage.md) — источник статусов требований; [контракт](frontend.md) — источник формата API. Оформление основано на [скриншотах Halyk](halyk-visual-style-analysis.md), не официальном брендбуке.

«Код реализован», «автотест прошёл», «проверено в браузере с fixture» и «проверено с реальным голосом» — разные уровни доказательства. Число тестов само по себе не подтверждает выполнение ТЗ банка.

После уточнения объёма удалены проигрыватель датасета, отдельная аудиодиагностика и статичный пример. Это не требования исходного ТЗ. Ниже сохранены исторические результаты их проверки; они не описывают текущие доступные экраны и не заменяют повторную проверку изменённого интерфейса. Новый браузерный прогон не выполнялся по просьбе пользователя.

## Автоматические проверки

Из корня репозитория:

```bash
npm --prefix frontend test
npm --prefix frontend run build
git diff --check
```

- Протокол: допустимые/некорректные события, RU/KK/mixed, формат PCM, идентификаторы, последовательности, HTTP timeout/abort.
- Состояние: последовательные события, восстановление snapshot, защита от устаревшего ответа, сохранение этапов при частичных таймингах, отсутствие выдуманного статуса выполнения.
- Аудио: порядок чанков, flush перед commit, отмена разрешения, остановка ресурсов, mute/replay, отсутствие повторной отчётности при replay, детектор тишины/уровень.
- Панель: выбранный против активного сценария, очередь/приостановленные, слоты/действия/handoff, фильтры, валидные медианы, безопасное отображение/экспорт.
- Fixture: preview/подтверждение/отказ/дубликаты, обрыв, mixed, handoff, частичные метрики, PCM-сигнал.
- Совместный запуск: локальные HTTP/WS, адрес API в Vite, binary PCM, завершение обоих сервисов, отказ на занятом порту без остановки чужого процесса.

Loopback-интеграция требует разрешения на локальный listener в ограниченном sandbox. Никаких внешних AI-вызовов эти тесты не делают.

Текущий прогон после удаления лишних функций и обновления оформления: **174 теста прошли**, production-сборка TypeScript/Vite и `git diff --check` успешны.

В том числе десять проверок реальной React-отрисовки без браузера (`workspace-scope.test.mjs`): только три раздела навигации, отсутствие статичного примера, сохранность микрофонных настроек/текстового ввода/управления звуком, отсутствие лишних подписей, отсутствие статуса соединения до начала звонка, локальная PNG-иконка Halyk вместо CSS-знака и удаление пункта «Рабочее пространство» при сохранении переключателя языка; дополнительно — выбранные значения/блокировка полей настроек, их казахская локализация и единственный свёрнутый блок метрик перед трассировкой в общей колонке. Нижняя строка с подсказкой записи и уведомлением о синтезированном голосе отсутствует; подсказка кнопки микрофона и блокировка ввода без соединения сохранены. Эти проверки не подтверждают взаимодействия в Chrome или физический звук. Исправление `confidence_estimate: null`, полученное через `git pull`, сохранено и покрыто API-тестами.

После переноса вкладок в navbar проверено: одна навигация внутри шапки, отсутствие её дубля в `main`, отдельные заголовки разделов и неизменённые подзаголовки RU/KK. В сумме 20 SSR-проверок оболочки, каталога и оценки (`workspace-scope`, `catalog-ui`, `evaluation-ui`). Во встроенном браузере подтверждены переходы «Разговор → Сценарии → Оценка → Разговор», отсутствие общего заголовка разговора в других разделах и сохранение заголовка/подтекста оценки. На 320 px с казахскими подписями все кнопки помещаются с переносом, ширина страницы равна ширине окна (320 px); переключатель языка доступен. Микрофон и AI-провайдеры не использовались.

После унификации заголовков обновлены те же 20 SSR-проверок: общий `header.page-intro`, новый RU/KK-подзаголовок редактора, заголовок оценки и экспорт над карточкой результатов. Во встроенном браузере на ширине 1280 px все три заголовка имеют одинаковые координаты (42, 119), размер 31 px, насыщенность 800 и подзаголовок 13 px. На 320 px с казахским интерфейсом координаты всех трёх заголовков (18, 198), размер 24 px, подзаголовок 11 px; горизонтального переполнения нет. На каждой вкладке виден только один `h1`. Это проверка оформления без запуска микрофона и серверного разговора.

После переноса метрик во встроенном браузере проверены раскрытие мышью, сворачивание клавишей Enter и порядок «метрики → трассировка». На ширине 390 px блок появляется вместе с мобильной вкладкой трассировки и раскрывается в потоке страницы. На desktop метрики и трассировка объединены в одну sticky-колонку; раскрытие метрик не перекрывает панель. Прогон без микрофона и серверного разговора.

Девять тестов `conversation-page-follow.test.mjs` покрывают автопрокрутку страницы возле конца чата, приостановку при чтении истории, первую явно отправленную реплику, восстановление/сброс и скрытые области. Во встроенном браузере на синтетическом localhost-стенде проверены три текстовые реплики с длинным содержимым: высота истории увеличилась до 2235 px при `clientHeight === scrollHeight`, внутреннего скроллера чата нет. На размере 1280 × 800 при прокрутке страницы на 800 px верх трассировки остался на 16 px; отправка следующей реплики внизу удержала конец чата в области просмотра. На исходном узком размере также подтверждено отсутствие внутренней прокрутки истории. Микрофон/AI-провайдеры не использовались; чтение истории во время длительного реального ответа и полный мобильный/Chrome-прогон отдельно не подтверждены.

Окно настроек микрофона отдельно проверено во встроенном браузере на localhost: шестерёнка рядом с «Чат», открытие кликом и Enter, закрытие по Escape, крестику и клику вне окна, возврат фокуса на кнопку, сохранение выбранного режима после повторного открытия. Визуально проверено окно на штатном desktop-размере. Запись, физические устройства и AI-провайдеры в этом прогоне не использовались; это не полный регрессионный прогон целевого Chrome.

Большая иконка поддержки проверяется как доступная кнопка голосового запуска (название, тип, видимость для скринридера, исходная доступность). Пять тестов `voice-call-start.test.mjs` покрывают одноразовое разрешение записи после готовности соединения, повторные клики, устаревшие события, отмену и отсутствие самозапуска после восстановления/переподключения. Это проверки управляющей модели; весь путь клика через реальный WebSocket и разрешение физического микрофона после этой правки в браузере не проверялся.

Исторический прогон до удаления дополнительных инструментов: **163 теста прошли**, production-сборка TypeScript/Vite и `git diff --check` успешны. Это не результат проверки текущего состава тестов и не оценка точности LLM.

Дополнительно покрываются: полный каталог 40+3, восстановление/импорт/ссылки/необратимые действия и вредоносные значения JSON; формулы 104 реплик и парного Full/Fast-сравнения; разрешения/поздний resume/autoplay/очистка PCM; allowlist эмоции и безопасный экспорт. Тесты удалённых проигрывателя и диагностического экрана больше не относятся к текущему составу продукта.

Команды выше проверяют клиентский код и изолированную интеграцию, не провайдеров/физическое аудио.

## Chrome и физическое аудио: исторический прогон 23.09.2026

До удаления дополнительных инструментов проверялся настоящий Google Chrome с локальным fixture (`127.0.0.1:5175`), не только встроенный браузер. Пользователь отдельно разрешил локальный микрофон и подтвердил на слух тестовый сигнал. Никакая запись не отправлялась AI-провайдерам.

Подтверждено в UI:

- Запрос разрешения Chrome → «Allow this time» → реальные PCM-кадры и RMS встроенного микрофона MacBook Pro. Имена устройств появились после разрешения.
- Явный выбор встроенного устройства; запись достигла лимита **15.00 s**, уровень вернулся в ноль и UI освободил микрофон. Предыдущий ранний лимит, включавший ожидание разрешения, исправлен: предел записи теперь отсчитывается после подготовки, ожидание разрешения ограничено отдельно.
- Тестовый двухсекундный сигнал: браузерный старт **50 ms**, пользователь ответил «Да, звук слышен». Это локальный проигрыватель, не AI end-to-end и не аппаратно откалиброванная задержка.
- Воспроизведение записанного PCM, остановка, mute/unmute; при mute кнопки проигрывания отключены. Запись очищается при выходе из диагностики.
- Редактор показывает 40 сценариев и 3 системных намерения; создан и удалён тестовый `CUSTOM_01`, исходный каталог восстановлен. Неприменённое имя сохранилось при переходе в аналитику и обратно. Отключение подтверждения SC02 блокирует применение. QA-правки отменены.
- Аналитика отвергла некорректный JSON; для искусственного прогона показала **2/104**, 102 отсутствующих результата. Парное сравнение по одному общему ID: 350 / 200 ms, разница −150 ms. Эти введённые числа проверяют математику UI, а не качество/скорость модели.
- Датасет: все 10 вариантов в селекторе, Enter показывает следующий шаг эталона; D10 целиком с переключением RU/KK и маскированием данных. API-режим создал отдельную сессию, отправил только первую клиентскую реплику, показал реальное несовпадение fixture `SC13, SC20` с эталоном `SC01`. Переход к трассе и обратно сохранил результат. Pending confirmation заблокировал следующий шаг до явного согласия.
- На ширине **320 px** датасет, каталог, аналитика и основной экран: `scrollWidth === innerWidth`, горизонтального переполнения страницы нет. Локальные таблицы могут прокручиваться внутри своих контейнеров.
- Измерение sRGB-текста обнаружило недостаточный контраст вторичных подписей основного экрана. Цвета затем затемнены; повторный браузерный замер после этой правки не завершён. Расчёт не являлся полным WCAG-аудитом и не оценивал OKLCH-фоны как sRGB.

Chrome остановил управление из-за открытого UI другого расширения. Пользователь явно попросил **завершить без дальнейшего браузерного прогона**. После этого выполнялись только сборка, тесты и документация; попытка сбросить временный viewport также была заблокирована расширением. Новые `/emotion` и финальные контрастные правки проверены кодом/тестами, но не повторным Chrome-прогоном.

Остаётся именно ручная проверка устройства/доступности, не отсутствующие продуктовые экраны:

- Отказ/повтор разрешения и физическое отключение/смена внешнего микрофона в Chrome. В автотестах эти ветки проверены, физический unplug не выполнялся.
- Контролируемая тихая речь → пауза → VAD: при наблюдаемом тихом фоновом сигнале пик 0.0179 был ниже порога 0.025, поэтому завершение произошло по лимиту диагностики, **не** по VAD. Нужен повтор с тестовой речью и подходящим порогом.
- Реальный запрет autoplay, полный клавиатурный проход/фокус, browser zoom 200%, reduced-motion и финальный повторный замер контраста. Реакции на autoplay rejection/поздний resume покрыты автотестами.

Передача разработчику backend для редактора, аналитики и эмоций — [frontend-labs.md](frontend-labs.md). Отсутствие интеграционной приёмки здесь не считается отсутствием реализованного frontend.

## Браузерная проверка с fixture

Запуск: `npm --prefix frontend run dev:fixture`. Адрес: `http://127.0.0.1:5175`. Только синтетические данные. Команды описаны в [общем README](../../README.md#fixture).

Ниже сохранены результаты **предыдущего прогона во встроенном браузере**, не текущая полная Chrome-приёмка. Ранее проверены старт/сброс, визуальный пример, RU/KK, две панели на десктопе и мобильное переключение, ширины 320/390/1200/1440 px, отсутствие API, текст/preview/reload/подтверждение/отказ/reconnect и TTS fallback. После расширения интерфейса необходимо повторить затронутые пути; не переносить автоматически результат прежней версии на новые контролы.

До удаления дополнительных инструментов в браузере с fixture наблюдались: 11 реплик без потери истории; основной SC13 против активного SC11 и очереди SC20; структурированные слоты/preview/подтверждение; возврат текста в черновик **без отправки**; безопасное сообщение `/error`; mixed-транскрипт; контекст handoff; сохранение частичных таймингов; PCM-сигнал с отдельной текстовой browser-метрикой, не включённой в голосовую медиану. Во время разработки HMR менял состояние; это промежуточные наблюдения, а чек-лист ниже предназначен для повторного прогона на свежем запуске окончательной сборки.

После обновления страницы на коде той версии отдельно подтверждены:

- Восстановление snapshot; `/slots` без дублирования preview-действия, корректный маскированный JSON в буфере обмена и отказ от действия.
- `/audio` создаёт PCM-ответ и **текстовую** browser-метрику (в этом прогоне 85 мс); значение синтетическое, не доказательство голосовой задержки. Проверен replay, затем завершение: история сохраняется, текстовый/аудиоввод отключены, таймер остановлен.
- RU/KK на 320 и 390 px без горизонтального переполнения; показаны настройки автозавершения и ползунок паузы. Наличие контролов не подтверждает детекцию тишины на физическом микрофоне.

Составные пункты ниже остаются открытыми, пока не проверены **все** их условия; эти наблюдения не закрывают непроверенные hardware/доступность/внешние компоненты.

- [ ] Начать звонок, проверить длительность и состояние соединения в панели разговора; завершить — история остаётся, ввод отключается; «Новый звонок» очищает историю и аудио.
- [ ] В RU и KK пройти обычное сообщение → preview → подтверждение; отдельно отказ. До серверного результата UI не пишет «выполнено».
- [ ] `/context`: активный SC11 отличен от основного SC13, SC20 в очереди, SC13 приостановлен.
- [ ] `/slots`: пять состояний слотов, источник/сценарий, preview/ошибка действия; неизвестные сведения не заменены предположениями.
- [ ] `/handoff`: причина, очередь, контекст и `context_received`; нет утверждения о подключении реального оператора.
- [ ] `/mixed`: нет разрыва WS; язык mixed и исходный транскрипт сохранены.
- [ ] `/partial-metrics`: все этапы остались после второго обновления; browser и server показатели разделены.
- [ ] `/error`: маркер `DO_NOT_DISPLAY_FIXTURE_DIAGNOSTIC` и fake token/prompt отсутствуют в UI, копировании и JSON.
- [ ] `/audio`: синтетический сигнал, остановка/mute/replay, снятие блокировки. Это проверка транспорта, не голоса STT/TTS.
- [ ] `/disconnect`: восстановление без повторной отправки; pending confirmation не выполняется само.
- [ ] Фильтры язык/сценарий/статус, отсутствие результатов, старая реплика, копирование и экспорт маскированного JSON.
- [ ] Не менее 10 пользовательских реплик: история/трассы не исчезают, тайминги не смешиваются; ручная прокрутка сохраняется.
- [ ] 320 px, desktop, RU/KK, длинные строки, zoom, клавиатура, видимый focus, `aria-live`, reduced motion; нет горизонтального переполнения.

### Дополнительная проверка предыдущей версии

До удаления дополнительных инструментов проверены «Новый звонок» (история и аудио очищаются), запуск клавишей Enter, `/disconnect` → восстановление без дублирования реплики, снятие сообщения о восстановлении после подключения. В новой вкладке пройден казахский путь: создание сессии → синтетическое сообщение → preview → кнопка «Растау» отправляет ровно `Иә, растаймын` → завершение. Ошибок JavaScript в этой чистой вкладке не зафиксировано. Тестовый ответ намеренно не используется для оценки качества казахского языка модели.

## Обязательный прогон с реальным API и устройством

- [ ] Запуск **всего** решения одной документированной командой из свежей рабочей копии; секреты только на сервере.
- [ ] Создание сессии, origin/CORS, `session.ready` с правильным ID, полный каталог SC01–SC40 и системные намерения.
- [ ] Микрофон: разрешение, отказ, отсутствие устройства, повтор после смены разрешения, выбор устройства, отключение во время записи.
- [ ] Отпустить запись, пока запрашивается разрешение: позднее разрешение не начинает запись, поток освобождён, отображается отмена, пустой `turn.commit` не отправлен; новая запись — только по новому действию.
- [ ] Push-to-talk указателем и клавиатурой; отпускание за пределами кнопки/потеря фокуса; `turn.start → PCM → последний PCM → turn.commit`, конец фразы не обрезан.
- [ ] Автозавершение: тихая речь, паузы, шум, настройка порога/паузы и ручной резерв. Включение не запускает запись без действия пользователя.
- [ ] Разрыв сети во время разрешения, записи, обработки и ответа; устройство освобождается, событие/действие не повторяется автоматически.
- [ ] 60 секунд без событий во время обработки: watchdog запускает восстановление, не повторяет ввод и не объявляет действие выполненным/отменённым без snapshot.
- [ ] Реальные RU/KK/mixed-реплики: транскрипт, смысл, сценарии, язык ответа, казахское произношение на слух.
- [ ] Воспроизведение при паузах между чанками, autoplay-блокировке, mute, stop и replay. Replay не создаёт новый `playback.started`.
- [ ] Сверить browser timing со звуком на устройстве; исключить replay, текст, отсутствие звука и fixture из голосовой бонусной выборки.
- [ ] Показать все этапы, router-ориентир 500 мс и медиану голосового end-to-first-audio; не обещать баллы по серверным/синтетическим значениям.
- [ ] Мультинтент со срочным сценарием, смена темы, возврат к прерванной, продолжение слота; frontend не пересортировывает решение самостоятельно.
- [ ] Идентификация синтетического клиента; факты только из стартового набора, дата среза `2026-10-01`.
- [ ] Подтверждение/отказ голосом и кнопкой, неопределённый ответ, смена темы перед подтверждением, разрыв после согласия. Исполнение/идемпотентность доказываются серверными тестами.
- [ ] Один уточняющий вопрос; низкая уверенность/просьба клиента → оператор с причиной, очередью, контекстом.
- [ ] 404/истечение сессии, медленный API, исчерпание reconnect, дубликаты/устаревшие события, `stt_unavailable`, `router_unavailable`, `tts_unavailable`, `action_failed`.
- [ ] Dev-набор: `evaluate.py` на 104 репликах с RU/KK/mixed/type breakdown; 10 размеченных диалогов. Ожидаемые ответы не подменяют результат модели.
- [ ] Chrome на ноутбуке — основной браузер демонстрации; отдельно Safari/мобильные устройства, если заявляется их поддержка.

## Границы

Frontend не выбирает сценарии, не считает страховые тарифы, не выполняет действия и не гарантирует серверную безопасность. Маскирование — дополнительная защита, не разрешение использовать реальные данные. Fixture `/audio` не проверяет микрофон или STT/TTS. Формальный WCAG-аудит, скрытый набор жюри и полная голосовая приёмка пока не выполнены.
