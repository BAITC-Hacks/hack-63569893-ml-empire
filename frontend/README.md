# Voice Router frontend

React + TypeScript: голосовой веб-симулятор и панель супервизора в визуальном стиле Halyk. Предметная область — **вымышленная Saqta Insurance** из стартового набора, а не реальные банковские продукты. Используйте только синтетические клиентские данные. Голос помощника синтезирован ИИ.

Клиент реализует [HTTP/WebSocket-контракт](docs/frontend.md). Backend разрабатывается отдельно; после объединения веток нужна интеграционная приёмка. Тестовый сервер не заменяет LLM/STT/TTS и не подтверждает качество маршрутизации. [Матрица требований и баллов](docs/requirements-coverage.md) отделяет клиентскую реализацию от проверок всего решения. По запросу команды в frontend включены и дополнительные пункты ТЗ; их сценарии и границы описаны в [руководстве лабораторных инструментов](docs/frontend-labs.md).

## Установка и запуск

Из корня репозитория:

```bash
npm --prefix frontend ci
```

Рабочая среда проверок — Node.js 25.2.1; тесты используют встроенный запуск TypeScript, поэтому старые версии Node без этой возможности не подходят. Секреты LLM/STT/TTS нельзя добавлять в `.env.local`, переменные `VITE_*` или код браузера.

### Реальный API

```bash
npm --prefix frontend run dev
```

Vite напечатает локальный адрес. По умолчанию `/api` проксируется на `http://localhost:8000`. Для другого API задайте **только публичный адрес** `VITE_API_BASE_URL` в `frontend/.env.local` по примеру `.env.example`. Этот режим никогда не подменяет недоступный сервер фиктивными ответами.

Для production: `npm --prefix frontend run build`, затем разместите `frontend/dist/` на HTTPS-origin с настроенным API/WS. CORS и проверка WebSocket origin настраиваются на бэкенде. Доступ к микрофону требует HTTPS либо localhost.

### Одна команда для локальной проверки клиента

```bash
npm --prefix frontend run dev:fixture
```

Команда запускает **синтетический тестовый API** на `http://127.0.0.1:8011` и интерфейс на `http://127.0.0.1:5175`. Браузер автоматически не открывается. `Ctrl+C` останавливает оба запущенных сервиса. Если порт занят, запуск завершается с объяснением; чужой процесс не останавливается, порт не меняется незаметно.

Это одна команда **для клиентского QA**, не выполнение требования банка о запуске полного LLM/STT/TTS-решения одной командой. Полный запуск остаётся задачей интеграции с [бэкендом](../docs/superpowers/plans/2026-09-23-voice-router-backend.md).

## Синтетический QA-сервер

Нажмите «Начать разговор» и отправляйте команды текстом. Все ответы помечены `[Тестовый сервер]`; сервис слушает только loopback и использует данные в памяти. Обычное сообщение создаёт тестовое ожидающее подтверждение. Кнопки согласия/отказа проверяют соответствующие ветки; реальные заявления и другие операции не создаются.

| Ввод | Что проверяет |
| --- | --- |
| Любой обычный текст | Две выбранные задачи, альтернативу, preview и текстовый fallback при недоступном TTS |
| «Да, подтверждаю» / «Иә, растаймын» | Явное согласие следующей репликой; повтор одного `turn_id` ничего не исполняет повторно |
| «Нет, отказываюсь» / «Жоқ, бас тартамын» | Отказ без выполнения действия |
| `/handoff` | Причину, очередь, статус `context_received` и контекст; реальный оператор не подключается |
| `/slots` | Структурированные значения/источники/статусы слотов и состояния действий |
| `/error` | Безопасное сообщение по коду; внутренняя диагностика не должна попасть в UI/экспорт |
| `/mixed` | Исходный смешанный транскрипт и язык `mixed` |
| `/partial-metrics` | Частичные обновления таймингов без потери предыдущих этапов |
| `/context` | Отличие выбранного основного сценария от активного, очередь и приостановленную тему |
| `/emotion` | Синтетическое `trace.affect`: эмоцию, тон, источник и оценку модели; это не реальное распознавание эмоции |
| `/audio` | Три PCM-чанка тихого синтетического сигнала длиной 300 мс; **это не TTS, не голос и не распознавание** |
| `/disconnect` | Один искусственный обрыв за сессию с восстановлением без автоматической повторной отправки |

Микрофонный ввод этот сервер не распознаёт. Для реальной голосовой демонстрации нужен настоящий API. Кнопка «Посмотреть пример» — отдельный явно обозначенный статичный визуальный пример, без маршрутизации и отправки данных.

## Возможности клиента

- Новый звонок, отдельное завершение с сохранением истории до сброса, длительность и состояние подключения.
- Ручная запись push-to-talk, выбор доступного микрофона, индикатор уровня, включаемое окончание по тишине с ручным резервом; пауза 800–2500 мс и порог RMS 0.005–0.08 для тихого голоса; PCM16 mono 24 kHz через AudioWorklet.
- Текстовый резерв, partial/final транскрипт, RU/KK-интерфейс, исходная mixed-речь, история и безопасное возвращение неудачной текстовой реплики в черновик.
- Потоковая очередь PCM, остановка звука, mute, replay имеющегося аудио; текст остаётся при ошибке TTS.
- Подтверждение/отказ голосом или кнопками как новая реплика. Выполненность действия определяет только сервер.
- Супервизор: транскрипт, выбранные/активный/ожидающие/приостановленные сценарии, приоритеты, причины, альтернативы, оценка модели, слоты, действия, уточнение, оператор и ошибки. Расширенные поля показываются только когда сервер их передал.
- Этапы задержки и медианы с количеством измерений; голосовой browser timing отделён от текстового и серверного. Фильтры по языку/сценарию/статусу, копирование и выгрузка маскированной трассировки.
- Защита от дублей и устаревших событий, ограниченный reconnect, восстановление snapshot, безопасные локализованные сообщения вместо сырых внутренних ошибок сервера.
- Редактор сценариев: формы/полный JSON, ссылки и безопасность действий, дополнительные сценарии, локальный черновик, импорт/экспорт. Изменения **не публикуются** в активный серверный каталог.
- Проигрыватель 10 диалогов: локальный эталон с шагами/паузой и отдельный ручной API-прогон, сравнение ожидаемых/фактических сценариев, маскированный экспорт. Эталонные метки не отправляются маршрутизатору, подтверждение не автоматизируется.
- Аналитика 104 dev-реплик: импорт predictions, формулы `evaluate.py`, пропущенные результаты, разрезы языка/типа/сценария, confusion и парное Full/Fast-сравнение по общим ID с реальными импортированными таймингами. В браузере benchmark не запускается.
- Эмоция/тон ответа по `trace.affect`: готовая клиентская поддержка аддитивного предложения контракта, требующего серверного mapping; без данных нет локальных догадок.
- Экран «Микрофон и звук»: запись до 15 секунд только в памяти вкладки, уровень/пик, выбор устройства, тот же PCM-путь, локальное прослушивание, тестовый тон, stop/mute. Запись не отправляется API/AI-провайдерам и удаляется при выходе из диагностики.

### Лабораторные инструменты

Откройте нужный раздел над рабочей областью. «Сценарии» и «Оценка и сравнение» работают с локальными JSON; «Диалоги датасета» отправляет данные серверу только в режиме API-прогона и по нажатию на очередной шаг. Перед новым прогоном история текущего разговора очищается. Настоящий API может использовать платных провайдеров.

Для оценки загрузите, например, файл формы `{"U001":["SC01"],"U002":[]}` в Full или Fast. Это пример структуры, не измеренный результат. Не предоставленные ID считаются ошибками на всех 104 эталонных репликах; частичное покрытие явно видно. Тайминги принимаются только как числа в `latency_ms`, с явным `latency_stage` для парного сравнения. Форматы, формулы, приватность, хранение черновика и инструкция backend-разработчику: [frontend-labs.md](docs/frontend-labs.md).

Запросы HTTP и ожидание `session.ready` ограничены 10 секундами. Если во время обработки/ответа 60 секунд нет событий, клиент закрывает зависший сокет и восстанавливает состояние. Переподключение: до четырёх попыток с паузами 1, 2, 4, 8 секунд; затем ручное восстановление. Незавершённая реплика не отправляется повторно автоматически. Клиентское завершение отключает микрофон/аудио/соединение; текущий контракт не содержит серверного endpoint завершения звонка.

Остановка текущего звука не отменяет серверную обработку: оставшиеся входящие чанки сохраняются для последующего replay. В режиме автозавершения клиент учитывает фактически накопленный интервал тишины в замере задержки; детектор является эвристикой и не доказывает точное время окончания речи или физического звука.

В `sessionStorage` сохраняются метаданные подключения, не архив разговора. История и аудио доступны в памяти текущей страницы; новый звонок очищает их. После reload восстанавливаются только реально полученные поля последнего snapshot, включая текст/язык/маршрут, **если** они присутствуют в `last_trace`. Отсутствующие ответы и статус исполнения не придумываются.

Для восстановления классификации сервер передаёт `last_trace.route` в полной форме `route.decision.payload`, а `last_trace.transcript` — строкой либо `{text, language}`; [пример snapshot](docs/frontend.md#адреса-и-подключение). Отдельные top-level `last_trace.scenarios` не заменяют вложенный route.

Если отпустить кнопку до завершения запроса разрешения микрофона, подготовка отменяется без отправки пустой реплики. Позднее предоставление разрешения не включает запись автоматически: нажмите кнопку снова.

## Проверка

```bash
npm --prefix frontend test
npm --prefix frontend run build
git diff --check
```

Тесты покрывают протокол, восстановление и метрики, маскирование, аудиопоток, определение тишины, модели панели, каталог/ссылки/подтверждения, датасет/сопоставление, математические формулы/импорт оценки, допустимые эмоции/тон, локальный аудиобуфер, fixture и совместный запуск. Интеграционные тесты открывают временные loopback-порты; sandbox может запросить разрешение. Это не тесты реальных провайдеров.

[Чек-лист проверки](docs/frontend-verification.md) фиксирует фактически выполненные проверки Chrome/устройства и открытые условия. Качество настоящих RU/KK STT/LLM/TTS, голосовая end-to-end задержка и скрытые реплики жюри требуют отдельного серверного/интеграционного прогона. Полное соответствие всей системы и итоговые баллы **не заявляются**. Полный WCAG-аудит и проверка всех браузеров не проводились.
